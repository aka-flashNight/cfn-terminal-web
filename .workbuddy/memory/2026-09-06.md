## 立绘显示逻辑：回退到固定源尺寸方案（重要，勿再改）

曾尝试把立绘改成「按 naturalWidth/Height 动态缩放到 600px 高」，结果立绘明显变小且跑偏到中间，用户要求回退。
**现方案（与 commit b266a7f 一致，已验证正确）**：
- 固定按 SWF 导出源图 4096×2304 计算：`ILLUST_SCALE = 600/1600 = 0.375`，
  显示尺寸固定 `1536×864`（`ILLUST_DISPLAY_WIDTH × ILLUST_SCALED_HEIGHT`），与后端实际返回的 PNG 尺寸**无关**。
- X 边界由 alpha 扫描得到，采样画布固定 2048×1152，只扫 `y ∈ [100,1600]` 对应带，结果按 `ILLUST_SOURCE_WIDTH/2048` 换算回 4096 坐标系。
- 扫描失败用 `ILLUST_DEFAULT_BOUNDS = {left:200, right:2300, centerX:1250}` 兜底。

结论：后端换用 manifest 立绘（尺寸变小但比例不变）后，**仍要用固定 4096×2304 坐标系 + 固定缩放**，不要用图片真实尺寸动态计算。
